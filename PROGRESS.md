### Added

- (2026-08-07) Added continuous integration that runs every test suite in this repository on a pull request, because nothing automated had ever run most of them. Three local verification tiers fire on commit, on push, and on pull request creation, and all three resolve to a single configured test command that reaches only one of the three suites here — 466 tests. The other two, 376 shell tests and four Python suites, were run by nothing at all: not the tiers, and not continuous integration, because there were no workflows. That explains a puzzle noticed earlier, that fourteen tests fail and nothing tracks them; every gate reported success over a suite it never looked at. The fix belongs on a runner rather than in a stricter local gate, because the shell suite takes three and a half minutes and the push tier re-runs tests on every push once a pull request is open, so enforcing it locally would tax every push during a review cycle. On a runner it overlaps the automated review that already happens and costs no waiting. It runs on macOS to match the machine these tests were written against, and each suite runs even when an earlier one fails so that one failure cannot hide the rest.

- (2026-08-02) Repaired drift between the interactive and autonomous copies of the PRD skills, which are hand-mirrored and had failed to mirror in both directions. The autonomous `prd-done` fetched only one of the three channels CodeRabbit posts to, missing the review bodies where most findings live and the conversation channel where rate-limit notices appear. All three now get fetched, along with guidance on a subtler trap: no combination of empty responses proves a review happened. "Reviewed and found nothing," "rate-limited and never ran," and "reviewed an older commit" are indistinguishable from absence alone. A rate-limit notice proves the middle case; its absence proves nothing. The check that works is comparing the PR head SHA against the `commit_id` on CodeRabbit's reviews and inline comments. Two details matter: take the head SHA from the API rather than `git rev-parse HEAD`, since the local head diverges from the PR head whenever commits are unpushed and CodeRabbit reviews what was pushed; and check both channels, because a round can produce a review body with no inline comments or the reverse. It also had no re-review step after pushing fixes. The interactive `prd-done` was missing acceptance-gate detection and the `run-acceptance` label, which the global `CLAUDE.md` claims `/prd-done` applies automatically. Both variants also treated a missing `.github/release.yml` as a reason to skip labeling entirely, which would have dropped `run-acceptance` in any repo that runs an acceptance gate without release metadata; the two detections are now independent. - (2026-08-02) Added `--paginate` to the three-channel CodeRabbit fetch everywhere it is documented. Without it each call returns only the first 30 results, so a PR with many findings silently reports a subset — the same class of partial-review failure the three-channel fix addresses. The filter has to stay a streaming one (`.[] | {...}`) rather than a wrapped array, because gh applies `--jq` per page and a wrapped filter emits one array per page. `--slurp` is not an option here: gh rejects it with "the `--slurp` option is not supported with `--jq` or `--template`", confirmed by running it. The command lived in five documented places; all five now match, and `git-workflow.md` records the `--slurp` trap so it does not get re-suggested.
