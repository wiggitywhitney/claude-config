### Summary
The developer implemented M4 of the autonomous PRD execution system — a SessionStart hook that detects when an autonomous Ralph loop is running in the current repo and warns interactive sessions before they collide with it.

The core implementation involved creating `scripts/check-autonomous-run.sh`, a new SessionStart hook that reads `.claude/autonomous-run.local` (written by the orchestrator on startup), checks whether the PID it contains is still alive using `kill -0`, and surfaces either a "running" warning or a "stale marker" warning to stderr so it lands in Claude's `additionalContext`. The hook also needed to suppress itself in child sessions — the developer updated `scripts/autonomous-prd.sh` to set `AUTONOMOUS_PRD_CHILD=1` before each `claude -p` spawn, and the hook checks for this env var at the top and exits silently if set. This prevents children from seeing a human-facing "don't make edits" warning in their own context, which could confuse them into not doing their assigned work.

The developer registered the new hook in `config/settings.json` and added `.claude/autonomous-run.local` to `.gitignore`. They also wrote a 7-test bats suite covering all four states: child suppression (env var set), absent marker (silent exit), live PID (running warning), and dead PID (stale warning). The tests use the current shell's `$$` to simulate an alive process and a killed background process to simulate a dead one.

Before implementation, the developer had concerns about the design and wanted to verify it against Claude's actual behavior. They asked whether `claude -p` headless sessions fire SessionStart hooks the same way interactive sessions do, and whether there were better coordination mechanisms than file markers. The research confirmed that `claude -p` children do fire all SessionStart hooks identically to interactive sessions (only `--bare` mode suppresses hooks, but bare mode also strips skills and the full toolchain that autonomous children need). This finding was critical — it meant the hook would fire in every child the orchestrator spawned unless explicitly suppressed. The developer documented this in a new research section under "Concurrent sessions and SessionStart hook behavior" and added Decision 9 to the PRD, explaining why the `AUTONOMOUS_PRD_CHILD=1` env var suppression pattern is required and how it differs from the file-marker approach used for YOLO skill detection (Decision 8).

The developer also updated the M4 section of the PRD to reflect the new scope: the env var suppression is now a required part of the implementation, the success criteria include verification that children don't see the warning, and the end-to-end validation (M6) now includes a specific check for child suppression. They cascaded this decision to M6 and M7 so documentation and validation account for the suppression mechanism.

### Technical Decisions
**DECISION: SessionStart hook suppression in `claude -p` child sessions via environment variable** (Implemented) - FILES: scripts/autonomous-prd.sh, scripts/check-autonomous-run.sh, prds/84-autonomous-prd-execution.md
  - `claude -p` headless sessions fire all SessionStart hooks identically to interactive sessions
  - Without suppression, each child's `additionalContext` would contain the human-facing warning "Avoid manual edits or `/prd-next` invocations"
  - This could confuse children into not doing their assigned work
  - Environment variable is lightweight, forwarded automatically by the shell, requires no file or socket coordination
  - Distinct from the file-marker approach used for YOLO skill detection (Decision 8) — env var is hook suppression only, not mode detection
  Tradeoffs: An env var adds a new mechanism alongside the file marker, but the two coexist without conflict and each solves a distinct concern

**DECISION: Four-state detection logic for autonomous run marker** (Implemented) - FILES: scripts/check-autonomous-run.sh, tests/check-autonomous-run.bats
  - Child session suppression: if `AUTONOMOUS_PRD_CHILD` is set, exit silently with no output
  - Marker absent: exit silently with no output
  - Marker present with live PID: surface "running" warning to stderr with PID, start time, and PRD number
  - Marker present with dead PID: surface "stale marker" warning to stderr indicating previous run may have crashed
  - PID liveness checked via `kill -0 $PID` standard pattern
  - Stale markers are not auto-removed — surface and let user decide

**DECISION: Orchestrator sets `AUTONOMOUS_PRD_CHILD=1` before each `claude -p` spawn** (Implemented) - FILES: scripts/autonomous-prd.sh
  - One-line change at each spawn site: `AUTONOMOUS_PRD_CHILD=1 claude -p "$PROMPT"`
  - Applied to both milestone spawn and final `/prd-done` spawn
  - Prevents children from triggering the collision warning in their own `additionalContext`

**DECISION: SessionStart hook outputs warnings to stderr for `additionalContext` integration** (Implemented) - FILES: scripts/check-autonomous-run.sh
  - Warnings written to stderr so Claude Code picks them up as `additionalContext`
  - Follows the pattern established by `scripts/auto-reanchor.sh`
  - Always exits 0 (advisory, not a gate)

**DECISION: Marker file format and parsing approach** (Implemented) - FILES: scripts/check-autonomous-run.sh
  - Marker file contains `PID=`, `STARTED=`, and `PRD=` fields on separate lines
  - Parsed using `grep` and `cut` rather than sourcing to avoid executing untrusted file content
  - Marker path derived from `git rev-parse --show-toplevel` to work across all repos

**DECISION: Test coverage for all four detection states** (Implemented) - FILES: tests/check-autonomous-run.bats
