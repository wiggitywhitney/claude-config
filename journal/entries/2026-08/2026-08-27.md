## 6:37:19 AM CDT - Commit: 279b831

### Summary
The automated code review that runs before every push was silently discarding its own findings. The script captured all output from the review tool and then filtered it, printing results only when a line started with one of three specific patterns: `^File:`, `^Type: potential_issue`, or `^Comment:`. When the review tool changed its output format, none of those patterns matched anymore, so the review kept running for minutes on every push while its findings vanished into silence. Because a review that found problems now looked identical to a review that found nothing, and identical to the tool not being installed at all, there was no warning sign that anything was broken.

The developer removed the filter entirely. The review now prints straight through without any capture or pattern matching, staying advisory so it still never blocks a push, but its output is no longer lost. The fix came from noticing that a push produced no review output at all when the wrapper should have printed a header unconditionally — that header was being captured by the filter too.

Three new tests were added to prevent this from happening again. They verify that output matching none of the old patterns surfaces correctly, that a review reporting itself skipped gets shown, and that a review exiting with a non-zero status stays advisory. All three tests failed before the change.

The developer also fixed an existing test that couldn't actually fail. It committed a `.txt` file, which counts as documentation-only, so the script exited before reaching the review block entirely — the test's assertion held whether or not the skip behavior was working. That test now commits a source file and uses a stubbed reviewer that must not run, so it'll catch if the skip setting stops being honored.

The test suite shows 43 of 47 tests passing. The four failures are a documented baseline — they all fail at `git add prds/...` because of a personal global ignore rule, unrelated to this change.

## 8:21:24 AM CDT - Commit: 4d0a5fc

### Summary
The developer removed the code review from the pre-push hook, consolidating it into the milestone-time progress-update workflow where it was already running as a duplicate.

The pre-push hook had been executing a CodeRabbit CLI review on every push, reviewing the entire branch against the remote main branch. This cost grew with branch age—once the branch accumulated enough commits, the review hit its seven-minute timeout without reporting anything, making it both expensive and silent. Meanwhile, the same review was already baked into the progress-update skill and ran once per milestone instead. The developer deleted the hook's copy of the review and removed the script file that only the hook called (`hooks/git/lib/coderabbit-review.sh`), keeping the review where it actually finishes and happens while work is still local.

The documentation was updated to clarify that the milestone-time review is now the only review between writing code and opening a PR, so skipping it means work reaches a PR unreviewed. The security check that gates pushes remained untouched, as did the requirement for a review before merging a PR.

Tests were rewritten to verify the hook no longer runs any review and that the security check still executes. A test guarding the `.skip-coderabbit` dotfile was deleted since that file no longer affects the hook—though it still works where it matters, on the PR merge gate.
