### Summary
The developer documented a data contamination issue discovered during IS scoring runs. The shared `eval-traces.json` file, written by a persistent OpenTelemetry collector, accumulates spans indefinitely without truncation—mixing traces from different targets and sessions together. A scoring run produced a false 70/100 score because it included spans from an unrelated target (`cluster-whisperer`) alongside the target under test. The documentation now instructs future scoring sessions to filter the trace file by service name and timestamp before scoring, store the filtered subset as run evidence, and redact machine-specific identifiers from resource attributes before committing. Earlier baseline runs (run-25 and run-26) are noted as unaffected since they predate the contamination window.
