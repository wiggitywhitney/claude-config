## 12:44:42 PM CDT - Commit: 4931bb4

### Summary
The developer corrected the review-coverage verification rule after observing a false positive during a live code review. The issue stemmed from GitHub's behavior of re-anchoring inline comments to the newest commit whenever their surrounding code remains unchanged—meaning an inline comment's commit ID can point to a newer commit than the review that actually produced it. This caused a scenario where a review of an older commit appeared to cover the current head because the eleven inline comments had drifted forward while the review body remained pinned to its original commit.

The fix narrows the acceptance criteria to check only the reviews channel, which records the commit that was actually reviewed and does not move. The inline-comments channel is no longer accepted as evidence. The change includes documentation in both the workflow rules and the project progress log, with the specific observation from PR #119 recorded to prevent reintroducing the weaker version in the future.

## 7:47:42 PM CDT - Commit: 8f04e14

### Summary
The product requirements document for the Claude config audit redesign was updated to record two interconnected findings about how branch state affects runtime behavior in the installed configuration.

The developer documented that the rules directory, like the skills directory before it, is a symlink into the repository's working tree. This means every always-loaded rule follows whatever branch is currently checked out—not just skills. The review-coverage correction added in Decision 90 exists only on the current branch and is absent when the main branch is checked out, along with the incorrect guidance it replaced. This widens the scope of the branch-dependence problem from skills alone to all instructions the repository supplies, and expands the implications for the Milestone C1 migration decision accordingly.

The developer also added Decision 90 itself, which corrects a flaw in the documented test for whether a review covered a commit. The original rule accepted a match in either the review body or inline comments, but GitHub re-anchors inline comments to the current head whenever their diff hunks still apply, causing inline commit IDs to track the newest commit regardless of what was actually reviewed. This created a window where an in-flight review could be mistakenly counted as complete. The correction pins the test to the reviews channel alone, where the commit ID is stable and reflects what was genuinely reviewed. The developer noted this as the clearest example of the oversight problem Milestone C1 exists to address: a check that was documented, agreed upon, and wrong, surfaced only through accidental testing.
