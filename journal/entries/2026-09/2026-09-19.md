## 7:07:07 AM CDT - Commit: 7327864

### Summary
The developer resolved a disagreement between two documentation files about how Claude Code's sandbox escape hatch actually works by running three targeted probes against the system.

The question was whether a blocked command automatically retries unsandboxed (a harness-level fallback) or whether the model itself has to choose to re-run it with the escape parameter set. Two existing documents described the mechanism differently: `rules/claude-code-sandbox-gotchas.md` used phrasing like "by default" that could be read as automatic, while `docs/research/claude-code-permission-modes.md` described it as a parameter the model could pass. The developer designed three probes using `claude -p --settings` against a guaranteed-blocked write to `/tmp` to isolate which interpretation was correct.

The first probe ran the blocked command once with `allowUnsandboxedCommands: false`, confirming it stayed blocked with no retry path available. The second probe set `allowUnsandboxedCommands: true` (the default) but explicitly told the model not to retry or use the escape parameter — the command stayed blocked, proving no silent fallback occurred. The third probe gave the model free rein with the same settings — the model itself re-issued the call with `dangerouslyDisableSandbox: true` and succeeded.

This evidence settled the disagreement: the escape hatch is model-mediated, not automatic. The developer updated `rules/claude-code-sandbox-gotchas.md` to clarify that a blocked command only succeeds unsandboxed when the model chooses to retry with the parameter set, not through any harness-level fallback. They added a new subsection to `docs/research/claude-code-permission-modes.md` titled "The escape hatch is model-mediated, not a silent harness-level retry" documenting the three probes and their results as a lookup table. They also updated the PRD to mark this as Decision 95, closing Milestone B1's item 6, and revised the forward reference in Milestone C1's sandbox configuration section to note that the escape hatch question is now closed — `allowUnsandboxedCommands: false` remains the only setting that actually removes the model's option rather than relying on it not to use one. The PROGRESS.md file was updated with both this finding and a note about an earlier, still-unresolved question on rule compaction behavior.
