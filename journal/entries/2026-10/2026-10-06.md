### Summary
The developer corrected documentation about OpenTelemetry's `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` configuration variable in the semantic conventions gotchas rule. The previous documentation incorrectly stated that `EVENT_ONLY` was always the correct value and that `true` silently failed with no warning. In reality, the correct values and behavior differ between packages: Python's `opentelemetry-util-genai` rejects `true` (logging a warning and capturing nothing), while the JavaScript `@opentelemetry/instrumentation-openai` package expects `true` as a boolean and does not recognize `EVENT_ONLY`. The updated rule now lists the accepted values for each package, explains where captured content ends up in each case, and advises readers to check their installed package's source code before choosing a value rather than copying settings across languages. The changes were verified against the current source code of both the Python and JavaScript OpenTelemetry instrumentation packages.
