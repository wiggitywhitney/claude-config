### Summary
The developer updated the project's progress documentation and configuration files to reflect findings from Milestone B1 of the claude-config audit. The changes consolidated research on Claude Code's sandbox capabilities, context-loading behavior, and reviewer functionality into the project's main documentation files.

The PROGRESS.md file received substantial additions documenting four areas of investigation. First, the developer recorded gotchas for the command sandbox under the `--dangerously-skip-permissions` setting, confirmed through live testing: the sandbox still permits network access to unlisted hosts unless stricter allowlist settings are enabled; Go-based command-line tools like `gh` and `vals` failed inside the sandbox on macOS with certificate and timeout errors respectively, with a one-line exemption available as a workaround; the `excludedCommands` workaround matches literal command text rather than child processes a script invokes; and two specific macOS issues were documented involving git protocol failures and test runner flags. Second, two CodeRabbit CLI gotchas were added about credit-usage prompts appearing on later reviews in the same session and the CLI's self-update message pointing at Homebrew even when installed by other methods. Third, the developer documented corrections to existing guidance: clarifying that a code-review bot's refusal to re-review means the check already happened (not a reason to keep asking), fixing an installer gotcha that described a non-existent hooks-installation step, and correcting an overclaimed guarantee about the sandbox's escape hatch. Fourth, the developer recorded findings about project-level `@`-imports never resolving into context, multiple writing-voice rules, and a question about whether the coding assistant can natively stop risky changes before they land.

The configuration file received a single addition: `"feedbackDrafts": "off"` was added to turn off the assistant's background drafting of product feedback during sessions.

The research documents were substantially expanded with empirical findings. The sandbox evaluation added a full section documenting the method used (using `--settings` to layer configuration without touching live setup), verification results (filesystem confinement and network filtering both work, with one tool exemption needed), and the trap that enabling the sandbox requires three settings configured together because defaults leave escape hatches open. The context-loading research closed a six-week-old question by confirming that project-level `@`-imports never enter context at all, making their byte cost zero for the byte budget. The permission-modes document was updated to reflect that the sandbox's per-domain prompt class is largely obsolete and that the escape hatch is model-mediated rather than automatic. The reviewer investigation found that three code-review implementations coexist, with the personal fork shadowing the bundled skill, and that Viktor's configuration contains a disabled all-Claude alternative rather than evidence he ran and rejected it. The audit-decisions log recorded that `UserPromptSubmit` now exists as a distinct hook event at version 2.1.278, capable of blocking or rewriting prompts.

Five new daily journal summaries were created documenting specific sessions from September 11, 18, 19, 20, and 21, capturing the investigation process, findings, and decisions made during the audit work.

The git-workflow rules received targeted updates: clarifying that a credit-usage prompt can appear on later reviews even after earlier ones ran without it, adding guidance on reading cost terms before proceeding automatically; adding a note that the CLI's self-update message points at Homebrew even when installed by other methods; documenting that journal entries produce fresh findings on almost every re-review and should be skipped; and adding a detailed explanation of how to detect when a code-review bot has actually reviewed a commit by checking the review's summary comment and the check description rather than relying on inline comments or the check's pass state.

The dot-agent-deck and sandbox gotchas files were updated with corrections: the installer gotcha was rewritten to clarify that hooks auto-install on every dashboard startup with no separate manual step needed, and the sandbox gotchas file received additions documenting the four specific issues found through live testing.
