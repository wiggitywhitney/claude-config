### Summary
The developer measured what happens to a project's own `@`-import statements when a long conversation gets compacted in Claude Code version 2.1.301, closing a research question that had been reopened after an earlier probe used an incorrect import path.

The measurement confirmed that an imported file sitting inside the project's working directory survives compaction and is re-read from disk at that moment—so an edit made mid-session appears after the next compaction but not before. An imported file outside the working directory never loads at all unless that project has approved external imports, which explains a previous observation from August where two imported rule files appeared to vanish at compaction; they had never loaded in the first place. The developer also found that compaction can now be triggered in a scripted, non-interactive session using a single `claude -p --input-format stream-json` process, which an earlier note said was impossible.

The developer updated four documentation files with these findings and their implications: the main research document on context loading and compaction, the audit decisions log, the load findings record, and the project requirements document. The updates cascaded Decision 103 into related milestones and narrowed the remaining open questions to interactive mode behavior with external imports and what happens when an approved external import survives compaction.
