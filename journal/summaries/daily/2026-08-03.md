# Daily Summary — 2026-08-03

## Narrative

The developer spent the day on two major work streams: fixing infrastructure issues and executing the first measurement phase of PRD #109, a Claude Code configuration audit redesign.

The morning started with infrastructure cleanup. A post-commit hook for generating journal entries was failing silently because it couldn't find the API key needed to call the Anthropic API. The hook was falling back to `npx` instead of using the intended `node` path that vals wraps with secrets. The developer fixed this by linking the commit-story package locally, which restored the working code path and generated backlogged journal summaries from July. While handling that, they also captured two writing-voice rules from real communication examples — one about conversational phrasing for episode angles, another about explicitly labeling Slack channel references.

The audit work itself consumed most of the day. The developer completed Milestone A1 by gathering and cloning 19 reference repositories across Viktor Farcic's work, Michael Forrester's public repos (filtered from 60 down to 11 after manual review and AI-assisted triage), and their own repositories. A two-stage triage process removed clear dead ends using Haiku 4.5, leaving seven Michael repos with reusable Claude Code or agent-configuration material. This involved careful documentation of what was included, excluded, and why — the decision log now catalogs 49 excluded repos with explicit reasoning for each exclusion category.

Then the developer tackled Milestone A2, which measures what actually loads into Claude Code sessions. They built a re-runnable script that inventories every rule file and skill, how it gets loaded, its byte cost, and whether it survives context compaction. This revealed three important findings. First, `rules/README.md` was loading in every session at 7,477 bytes (roughly 3,100 tokens) despite having been moved from one always-loaded location to another — the benefit the move promised never happened. The developer fixed this by adding path-scoped frontmatter so the file only loads when working on rule files, removed a false exemption from the checker script, and added tests asserting the opposite of what they previously asserted. Second, the always-loaded set is larger than previously measured because `~/Documents/Journal/CURRENT-CONTEXT.md` loads every session but was invisible to local directory sweeps. Third, eight skills exceed or approach the 5,000-token compaction truncation cap, including `prd-done` where the merge and cleanup steps sit in exactly the region that gets cut off.

The developer also ran two research passes on Claude Code's documentation. One covers how the platform loads rules, skills, and CLAUDE.md files, what compaction does to each, and what the five load reasons mean. The other documents skill installation scope and discovered that skill precedence is personal-over-project — the reverse of rule precedence — invalidating four months of assumed autonomous behavior. They reconciled measurements against the user's `/context` and `/memory` output, confirming accuracy and identifying a token-per-byte ratio that corrected earlier estimates.

A critical measurement settled whether `@`-imported rule files survive context compaction. The developer installed a passive instrumentation hook in gitignored settings to avoid mutating tracked configuration, ran `/compact` in a session with roughly 230k tokens of history, and observed all 11 `@`-referenced rules reappeared with `load_reason: include`, confirming they survive because compaction re-reads root files from disk and re-resolving them pulls imports along. This finding gates the classification policy because every always-loaded rule arrives via `@`-reference.

The developer also restructured the entire PRD from nine sequential milestones into four ordered phases — Audit, Research, Design, and Disposal — moving all design work out of the early phases into a collaborative design milestone where it happens with all research inputs available. Milestone IDs were migrated from short codes like "M2" to spelled-out phase-prefixed names like "Milestone A2" using a script with atomicity guards, because short codes were unsafe to replace mechanically.

Throughout the day, the developer discovered and documented eleven approval-trigger classes in the Claude Code configuration, ranging from command-shape issues like `cd` chains and `$?` expansion to content-based triggers that fire on commit message patterns. They noted that seven of the eleven were discovered only because the developer screenshotted the approval prompts, making transcript mining more reliable than reasoning about what the checker probably inspects. They also recorded that documented discipline was violated five times in a later session, suggesting that guidance alone cannot address the failure mode and enforcement is needed instead.

The developer added detailed test coverage for the load-inventory script — 27 bats tests organized around classification decisions that matter for the audit. The tests verify how rules are loaded, whether they're loaded at startup, and whether they survive compaction. They also guard against specific defects like silently dropping `@`-references on macOS due to BSD grep treating `\s` as a literal character, and a size-dependent bug where SIGPIPE killed the upstream process when a match appeared near the top of a large file.

Late in the day, the developer withdrew a flawed recommendation to set `disable-model-invocation: true` on lifecycle skills. The documentation had claimed this would remove the skill's description from every session "at no behavioral cost," but that was backwards — the flag removes the model's ability to invoke the skill at all, creating a direct conflict with the project's autonomy goal. They corrected this across multiple documents as a genuine trade-off rather than a free cleanup task.

The developer also made several accuracy corrections throughout the research documentation. They qualified claims that had drifted back into being stated as fact, marked estimates as estimates rather than observations, corrected overclaims about what a single measurement could support, and fixed the decision log to follow its own rule about cross-referencing the PRD by decision text rather than number.

By day's end, Milestone A2 was complete with a measured inventory, verified against the platform's own reporting, and the audit had moved into the research phase with a solid foundation of evidence about what currently loads and what the platform offers.

## Key Decisions

- **Restructure the audit into four ordered phases — Audit, Research, Design, Disposal — moving all design work out of Phases A and B into a new collaborative design milestone** — The plan interleaved measuring, learning, and deciding, scheduling design before its inputs existed. Separating the three activities removes the defect where each decision was made with only part of the evidence. Milestones renamed to phase-prefixed spelled-out IDs (Milestone A1, B2, C1, etc.) to prevent AI from inferring wrong sequence from numeric order.

- **Settle `@`-import compaction survival by direct measurement** — Registered an InstructionsLoaded hook to observe that all 11 `@`-referenced rules reappeared with `load_reason: include` after compaction, confirming they survive because compaction re-reads root files from disk and re-resolving them pulls imports along.

- **Scope rules/README.md to load only when working on rule files** — File was loading unconditionally in every session despite being an index, costing approximately 3,100 tokens per session. Added path-scoped frontmatter and removed the false exemption from the checker script that had let the problem slide for four months.

- **Add a capability spike as the third research input, run before Viktor and Michael spikes** — Every plan-changing finding came from reading documentation rather than reasoning. Five capability findings from two narrow research passes, one invalidating four months of assumed autonomous behavior. Covers tools, hooks, settings, subagents, architectures — not only AI skills.

- **Autonomous variants are unvalidated drafts, not battle-tested code; every autonomous behavior promoted to default path needs live test first** — The autonomous variants have never executed anywhere — project-level YOLO symlinks in all nine repos are inert. Claude Code's skill precedence is personal-over-project (reverse of rule precedence), and all eight PRD skills are installed personally. Verified by live test; the interactive variant's description loaded despite project-level YOLO symlink.

- **"Autonomous-first" governs the default posture, not the choice of starting file** — Two separate axes: content (decided per divergence on merit regardless of which variant it came from) and default posture (where confirmation gates are the exception). The consolidated result is expected to match neither existing variant.

- **Add Test 0 to the classification policy — should this exist at all — ahead of every classifying test** — The draft policy sorted everything and deleted nothing, so bloat would survive in a tidier arrangement. Applies the principle "existence is not a reason to keep something" across all mechanisms.

- **Design conversations follow explicit protocol — explain evidence plainly, ask one question at a time, recommend one choice, write down each answer in the turn it is given** — Explain evidence as though Whitney has not read the documentation. One question at a time; ask, resolve, then ask the next. Write each answer down in the turn it is given, not batched at the end.

- **Separate the PRD, research docs, and decision log by content type to prevent bloat** — The PRD holds what to do. Research docs hold what was learned — findings, evidence, measurements. The decision log holds decisions, kept to a sentence or two, linking out to evidence rather than reproducing it.

- **Milestone names use phase-prefixed spelled-out IDs (Milestone A1, B2, C1, etc.) rather than short forms** — Short tokens are unsafe to find-and-replace; M7 is a substring of M7b. Spelled-out form is distinctive enough to match exactly, making the script trustworthy.

- **Separate confirmed skill truncation breaches from at-risk cases in measurement output** — Conflated confirmed cap breaches with dense-estimate risks under a single count. Recalibration revealed 7 confirmed and 1 at risk, not 8 total. Reporting them separately allows accurate assessment of which skills definitely lose their closing steps.

- **Track always-loaded budget components separately rather than summing into a single figure** — Components are not interchangeable: `include`-referenced rules are comparable with the baseline, while bare-rule files and skill descriptions are not. Summing them produces a figure that appears comparable when it is not.

- **Implement atomicity in the milestone-ID migration script via snapshot and restore** — Substitutions run in sequence, so a failure partway through would leave the PRD half-migrated. Snapshot taken before migration; on any non-zero exit the file is restored to pre-migration state.

- **Guard check-rule-frontmatter.sh against set -u empty array expansion on bash 3.2** — macOS's /bin/bash is version 3.2, which treats `"${arr[@]}"` on an empty array as an unbound variable and exits with status 1. Applied the guard pattern `${arr[@]+"${arr[@]}"}` to safely expand the array even when empty.

- **Document the bash 3.2 empty-array expansion trap with `set -u`** — Discovered when emptying an exemption array caused the checker to pass on PATH bash but abort under /bin/bash. The guard pattern prevents the unbound variable error on both bash versions. Developers should test explicitly with /bin/bash before trusting scripts that will run in hooks.

- **Withdraw the disable-model-invocation recommendation and correct it as a genuine trade-off** — The flag removes the model's ability to invoke the skill at all, leaving it reachable only when a human explicitly types the command. For autonomous workflows that need to reach those lifecycle skills on their own, the flag creates a direct conflict with the project's autonomy goal.

## Open Threads

This remains untested.

- **GitHub issue #24460 explanation remains unresolved** — Three different explanations remain consistent with the evidence (one manual compaction at version 2.1.220). The labeling explanation is preferred because it requires no one to have erred, but the matter is not closed.

- **Enforcement mechanisms are needed for approval-trigger discipline** — Documented discipline was violated five times in a later session, demonstrating that guidance alone cannot address the failure mode. Only enforcement or a changed default toolset can remedy this.

- **The coupled-pair classification challenge for branch-versus-main files** — A file changed on an unmerged branch and its counterpart on main are not automatically two places encoding one decision. Treating every branch diff as a pair would classify ordinary edits, additions, and deletions as pairs and bury real synchronization relationships in false positives. This belongs in Milestone C1's design rather than being resolved here.

- **Structured evidence mining from the `.claude/settings.local.json` allowlist** — The file contains 222 accumulated entries, many fossils of past prompts. It survives compaction and other history-loss events and is a cheaper evidence source than transcripts for understanding what commands prompted historically.
