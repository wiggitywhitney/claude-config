# Daily Summary — 2026-08-20

## Narrative

The developer spent the day working through an audit of the claude-config repository, making progress on PRD #109. They started early by capturing a writing voice rule—flagging "worth" as a potential AI tell when used in value-judgment phrasing like "that's context worth adding"—and committed it separately since it came up during other work.

The bulk of the morning went to fixing two broken parts of the setup script. The script had a hardcoded list of six skills to install when the repo actually contains twenty-four, so newly provisioned machines were missing eighteen skills needed for daily workflows. The developer switched both the install and uninstall paths to derive their lists from the actual directory structure instead. While fixing that, they discovered the script was also exiting with an error on every run because it still referenced a YouTube MCP safety hook that had been deleted earlier. That deletion had been recorded in four places—the live settings, the settings template, a test fixture, and a test assertion—but only the live settings had been cleaned up. The real problem was that the test suite was crashing at test three out of one hundred fifty-six, so it never reached the assertion that should've caught the stale hook path. The developer fixed the crash, moved two test functions that had been accidentally placed after the `if __name__ == "__main__"` block so they'd actually run, and replaced hardcoded expected values with ones derived from the template so future changes wouldn't break the tests. After these fixes, the suite went from aborting early to running all one hundred fifty-six tests, all passing.

The developer then measured document sizes across the project and found that the PRD and decision log had each roughly doubled since the original separation rule was established. Rather than just restating the rule, they noted that the growth included necessary corrections—creating a real tension between readability and accuracy—and recommended reconsidering how to measure growth instead of applying a single byte threshold. They also did a sweep for dead material: an empty `profiles/` directory from February that was never used, an archive of old hook code that git history preserves better than a stale copy, a couple of anki image scripts with no references outside the day they were written, and a migration script that should be removed when the PRD closes.

In the afternoon, the developer split a set of fourteen failing tests into two separate issues. Ten failures reproduce consistently on clean machines—a genuine bug with an unknown cause—so that became issue #115. The other four are environment-dependent; testing on a hosted machine revealed an additional forty-three tests that only pass locally because the machine has network access and specific repositories in place. Those findings and the absent CI became issue #116. The developer updated PROGRESS.md and the audit document to track the split and explain why combining them would've buried the fixable half inside an open-ended design problem.

Finally, the developer removed the `/cost-tracker` skill—a tool built in April for comparing token spend across repositories. Nothing invoked it, no README documented it, and they'd never actually used it. The removal was clean because there were no dependencies. What mattered was what the removal revealed: the audit had flagged that cost-tracker was the only skill not symlinked globally, recommending it be fixed. But the real question—whether anyone wanted the skill at all—was never asked. Once non-use was confirmed, the inconsistency became irrelevant. This became Decision 62 in the classification policy: ask whether something should exist before optimizing where it lives.
