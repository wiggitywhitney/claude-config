The original issue was that the setup script had switched to deriving the symlink list from current repository contents, which broke uninstall—when a skill gets deleted from the repo, its symlink remains behind pointing to nothing. The developer rewrote the logic to enumerate what's actually installed and remove anything pointing back into the repository, including dangling links.

The developer then triaged remaining findings against a rubric and updated documentation across multiple files, clarifying test failure counts, deferring settings template reconciliation to a separate issue, and marking obsolete milestone instructions as non-executable to prevent accidental re-execution.

Research into Claude's sub-agent capabilities surfaced a critical constraint: sub-agents cannot run a different vendor's model from their parent, which reframes mixed-vendor review strategies. The analysis showed that three of Viktor's four self-verification mechanisms are available today, but the fourth—mixed-vendor checking—isn't natively possible. CodeRabbit already serves that role in the workflow, though it runs at push time and requires manual triage.

The developer then made a bold decision to build and trial a code reviewer sub-agent immediately rather than design it later. Rather than using a generic review checklist, the trial was grounded in three real mistakes from the past week—each documented with the commit that fixed it. The reviewer's success hinges on whether it can catch these documented failures; if it cannot, it's not worth keeping.

The developer built three core artifacts for the diff-review system: a read-only reviewer sub-agent that hunts for four specific failure modes that have actually happened in this repository, a dispatch command that runs it against outgoing changes, and a push gate that blocks commits until a review verdict exists. The reviewer is read-only by design—the tool list omits `Write` and `Edit` entirely, so findings-only is enforced by the platform rather than by instruction. The push gate is a PreToolUse hook that can only refuse to proceed; it cannot spawn a sub-agent itself, but that refusal is the whole mechanism that makes review mandatory rather than optional.

The developer wrote 30 bats assertions across three test suites, all passing. However, the trial is incomplete—the reviewer hasn't been scored against the three benchmark diffs it was designed around, so the catch count doesn't exist yet. Three worktrees were deliberately left checked out at the commits that introduced each miss rather than the ones that fixed them, ready for scoring.

While working through the trial, the developer encountered and fixed several issues. A gate bypass existed where heredocs required special handling beyond quote-stripping to avoid false positives. The reviewer's documentation was overclaimed as "read-only" when it still had Bash access. A hardcoded user path was replaced with an environment variable. The developer also fixed a security bypass where quoted repository paths in `git -C "$REPO" push` commands were slipping through unchecked—the pattern would stop at the first space, capturing just the opening quote and half the directory name.

## Key Decisions

- **Reframe the PRD's problem statement from five original complaints to oversight and sub-agent orchestration.** The four original complaints had been resolved; the remaining opportunity was automating verification through sub-agents rather than manual review steps.

- **Elevate Milestone B2 (Viktor swarm workflow spike) to primary design source.** Viktor's and Michael's repositories became the basis for understanding how to reduce oversight rather than using them as comparison inputs.

- **Reverse Phase B execution order to run practitioner spikes before capability spike.** Reading capability documentation first establishes a fixed understanding that filters how practitioners' solutions are interpreted, invisibly narrowing the target. Studying practitioners first ensures their solutions are evaluated on their own terms.

- **Fix the uninstall path to remove dangling symlinks.** The setup script derived symlink installation from repository contents, but uninstall incorrectly used the same approach—leaving behind symlinks whose targets had been deleted. Uninstall now enumerates what's actually installed and removes anything pointing back into the repository.

- **Build and trial a reviewer sub-agent in Phase B rather than design it in Phase C.** Rather than designing in a vacuum, the trial is grounded in three real mistakes from the past week. If the reviewer can't catch these documented failures, it's not worth keeping, and discovering that is cheap.

- **Make the reviewer read-only by omitting Write and Edit tools.** A reviewer that can fix what it finds stops reporting and starts patching. Omitting edit tools makes findings-only a platform property rather than a request in prose that could be ignored.

- **Key verdict lookup to diff content hash rather than commit SHA.** A commit SHA doesn't change when the outgoing set grows because the remote is further behind, which ends with a verdict describing less than what's pushed. Keying to diff content invalidates the verdict when the diff changes.

- **Implement the push gate as a PreToolUse hook that denies until verdict exists.** A shell script cannot spawn a sub-agent, so it can only refuse to proceed. That refusal is the whole mechanism that makes review mandatory rather than a habit that decays.

- **Parse quoted repository paths in git -C arguments.** The natural form to write repository paths uses quotes, but the previous pattern stopped at whitespace, capturing only the opening quote and half the path. A quote-aware parser now handles double quotes, single quotes, and unquoted paths.

- **Correct byte-budget assumption about project-level import re-resolution.** The safe assumption for budgeting is the expensive one—assuming imports don't reload understates the always-loaded total by about 11,000 bytes and makes the budget too tight. The correct assumption is that imports are re-injected until measurement proves otherwise.

- **Assign the project-level import probe to Milestone B1.** The probe was floating between multiple milestones. Milestone B1 now owns running it to establish whether project-level imports are re-injected, with Milestone C1 budgeting conservatively if the probe doesn't run.

- **Mark Milestone A3's obsolete instructions as historical and non-executable.** A banner explicitly states "DO NOT EXECUTE ANY OF IT" to prevent a cold agent from reading cancelled imperatives as work.
