# Daily Summary — 2026-09-18

## Narrative

The developer spent the day documenting and evaluating a configuration audit project, with work falling into three main areas: establishing better communication patterns, conducting hands-on testing of sandbox and reviewer capabilities, and capturing practical gotchas from tool usage.

Early in the morning, the developer updated the global prompt guidelines to require that every question presented include pros and cons alongside a recommendation. This came from noticing that presenting bare choices forced analysis work to happen as a follow-up rather than upfront. The rule includes a practical exemption for trivial confirmations where tradeoffs are obvious.

The bulk of the work was a capability evaluation for Milestone B1 of the configuration audit project. Rather than surveying documentation, the developer actually enabled the command sandbox and ran tools inside it. This empirical approach revealed that earlier research claims needed correction: the sandbox now routes network domain approvals through a classifier instead of prompting the user for each new domain, and a concrete error (`x509: OSStatus -26276`) was traced to a certificate verification failure in `gh`, the only one of the tool family actually run — `gcloud` and `terraform` share the documented mechanism but were never tested. A one-line exemption fixed the `gh` issue. The evaluation also surfaced that enabling the sandbox requires three settings configured together—defaults leave escape hatches open—and identified two unsettled questions about escape-hatch behavior and Docker compatibility that need resolution before adoption.

On the code reviewer front, the developer investigated whether to adopt Claude-on-Claude review (same-vendor checking). Rather than running a new test, the developer found that Viktor, a trusted reference practitioner, has a commented-out all-Claude alternative in his live configuration — evidence of a standing preference, not proof he ran and rejected the same-vendor variant, since nothing establishes he ever executed it. This configuration evidence proved stronger than building a new evaluation, and the decision was made to decline the feature since mixed-vendor checking (which Claude Code can't provide) is essential to a reviewer's function.

The developer also discovered that three code-review implementations are installed simultaneously—a personal fork from April, an official plugin, and a bundled skill—and the oldest one wins by precedence. The fork can't simply be deleted because its `Defer` disposition opens tracking issues for real-but-too-large findings, while the bundled skill's equivalent outcome silently records nothing. Consolidating them requires replacing rather than absorbing that behavior, and renaming would affect five workflow references, so the work was deferred to the next milestone on phase-discipline grounds.

As the day progressed, the developer fixed documentation that had overstated claims. A statement that the built-in code-review feature was unreachable turned out to be too broad—it remains accessible through its shorter alias, just not the full command name. Claims about `gcloud` and `terraform` tool failures were narrowed to "mechanism-based inference" since only `gh` was actually tested. A procedural note about table numbering was rewritten to avoid stale row references.

The developer then committed four new gotcha files documenting practical problems: grammar packages for web-tree-sitter ship WebAssembly files that need separate installation; devbox lacks a documented Homebrew path and its init hook doesn't source as advertised; dot-agent-deck requires an explicit agent key per role or status tracking silently breaks; and Claude Code's sandbox has several defaults that weaken it. The developer also captured that the code-review tool confidently reports wrong findings about binary files and external API specs, and that hostname fields need separate redaction from ID fields. These were committed directly to main rather than a feature branch because rule files load from the working tree, and committing them to a branch would make them disappear until merge.

Late in the day, the developer incorporated findings from parallel work in other repositories: a new file documenting Python formatter differences (Black exits with failure code but still outputs source; Ruff outputs nothing), tightened cleanup procedures for partial branch checkouts, and adopted three writing-voice rules observed in actual messages. The developer also documented where new rule files must be committed and that the automated validator doesn't check whether rules are indexed, so files can pass validation and still be invisible.

Finally, the developer repaired two documented commands that couldn't work as written: a cleanup command that split filenames on whitespace was fixed to use NUL-delimited output, and a Python syntax-check one-liner that referenced an undefined variable was corrected to take the file path as an argument instead.

## Key Decisions

- **Require pros, cons, and recommendation with every question presented to the user** — Observing that bare choices forced follow-up analysis work, the developer added this to the global prompt guidelines with a practical exemption for trivial confirmations where tradeoffs are obvious.

- **Sandbox adoption as viable candidate for Milestone C1** — Empirically tested on the local install; filesystem confinement and network filtering both work. The `gh` TLS failure was traced to a specific Seatbelt profile denial and fixed with one exemption. Adoption requires all three settings configured together; defaults weaken the boundary. Two questions remain unsettled: escape-hatch mechanism and Docker-under-Colima compatibility.

- **Claude-on-Claude reviewer declined** — Viktor's configuration contains a disabled all-Claude alternative, providing configuration evidence stronger than running a new test. Mixed-vendor checking is essential to a reviewer's function, which Claude Code cannot provide.

- **Code-review skill consolidation deferred to Milestone C1** — Three implementations exist; the personal fork is stalest but cannot be deleted because its `Defer` disposition opens tracking issues while the bundled skill's `skipped` outcome records nothing. Consolidation requires replacing rather than absorbing that behavior. Deferred on phase-discipline grounds since Milestone B1 is research, not implementation.

- **Separate configuration evidence from run evidence** — Clarified that Viktor's approach shows disabled alternatives in his config, not measured verdicts from running them. Similarly, only `gh` was tested in the sandbox; `gcloud` and `terraform` remain inferences.

- **Document method notes for sandbox evaluation** — Captured how to safely test sandboxes: use `--settings` to layer config without touching live setup, establish unsandboxed baseline before testing, verify filesystem claims by disk state not reported messages, and use stdin for prompts when testing with multiple flags.

- **Record three unsettled claims from sandbox evaluation** — Docker under Colima, narrower `allowMachLookup` alternative, and a changelog gap where sandbox-relevant changes may exist but weren't fetched.

- **Record CodeRabbit CLI misreads binary files and external specs** — The tool reported correctly committed binaries as untracked and flagged external API attributes based on unrelated badges elsewhere in the file. Before accepting findings about binary state or external specs, verify independently with git commands and primary-source documentation.

- **Record hostname field leaking in evaluation traces** — `host.id` and `host.name` are separate fields; redacting one doesn't redact the other. Both must be included in sanitization checklists.

- **Record unsafe cleanup after partial-path branch checkout** — Instrument branches leave behind `.instrumentation.md` companion files. Capture the exact set of added paths before resetting, then delete only those; avoid `git clean -fd` which removes any untracked file under the paths.

- **Document Python formatter failure behavior differences** — Black exits with non-zero code but still outputs original source on parse failure; Ruff outputs nothing. Exit code should be the branch point for success detection, not stdout presence.

- **Tighten repository cleanup after partial branch checkout** — Use `git diff --diff-filter=A` to identify added paths instead of pattern-based deletion, then delete only those specific paths.

- **Document JSON Lines format of evaluation trace files** — Evaluation traces are one JSON object per line despite the `.json` extension. Converting to single-document JSON or renaming the extension breaks the scorer.

- **Adopt three writing-voice rules from actual message usage** — Lead updates with "I have some [topic] news!" instead of flat phrasing; qualify unfamiliar third parties as "someone named [Name]"; use "telemetry" instead of "payload" for non-implementation audiences.

- **Disable background feedback drafting in configuration** — The preference was already in effect locally and needed to be recorded in tracked configuration to prevent the assistant from queuing feedback reports during sessions.
