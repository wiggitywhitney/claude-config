They updated the documentation to clarify this, marked it as a decision in the PRD, and closed Milestone B1's item on this question.

## Key Decisions

- **Project-level `@`-imports do not re-resolve after `/compact` — only user-level imports do** — Measured by adding a temporary import to the project configuration file, registering a hook to log instruction-load events, and running compaction manually. The hook showed twelve import records from the user-level file and zero from the project file. However, the import was added mid-session, so the data cannot rule out "only loads at session startup, added too late" as an equally consistent explanation. Consequence for the byte budget is the same either way: project-level imports must be tracked as first-load-only.

- **The sandbox escape hatch is model-mediated, not an automatic harness-level retry** — Tested with three probes: one with the escape hatch disabled (stayed blocked), one with it enabled but the model instructed not to retry (stayed blocked), one with it enabled and the model free to act (the model re-issued the call with the escape parameter and succeeded). This settles that blocked commands only succeed unsandboxed when the model chooses to retry with the parameter set.

- **Document tree-sitter-python `with` statement grammar shapes** — `with_item` wraps its expression directly or in an `as_pattern` node when an `as` binding is present. `async with` mirrors `async def`'s pattern with an anonymous `async` child. Verified against tree-sitter-python 0.25.0 and web-tree-sitter 0.27.0.
