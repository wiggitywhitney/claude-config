# Daily Summary — 2026-09-28

## Narrative

The developer spent the morning closing out a research question that had been open since an earlier milestone. They were investigating whether Claude Code natively supports the kind of deterministic safeguards you'd find in a Coordinator pattern—things like snapshot-and-revert on failure, bounded retry loops, and exclusive-write scoping. After checking the documentation and running a live probe to verify that a `PreToolUse` hook could actually block Bash-based writes to protected files, they documented the findings: three of the five capabilities are buildable natively with the current architecture, one exists only in the embedded Agent SDK, and two have no native equivalent at all. The verdict was more favorable than originally thought—the pattern isn't a flat gap, just split across different architectures. They closed the milestone item and updated the research docs.

Right after that, the developer caught an overclaimed guarantee in the documentation they'd just written. The original text said a hook denying a file path gave the LLM "no path to touch that file," but that overstated what was actually tested. They narrowed it down to reflect only what the probe confirmed—a string-match pattern blocking a specific redirection command—and explicitly listed what wasn't tested, like indirect writes through variable substitution or symlinks. The distinction matters because a string-matching hook is a pattern gate, not a structural safeguard like the Coordinator uses.

Later in the afternoon, the developer updated documentation for OpenTelemetry Python to clarify the difference between `sys.exit()` and `os._exit()` in the context of span cleanup. `sys.exit()` raises a `SystemExit` exception, which lets `with` blocks clean up normally, while `os._exit()` terminates at the C level without unwinding the stack, leaving spans open. This distinction matters for span-leak detection rules, since treating both the same way produces false positives.

## Key Decisions

- **Pre-landing gate capability assessment against Coordinator pattern** — Deterministic safeguards comparable to the Coordinator pattern are partially native in Claude Code: pre-insertion static checks and exclusive-write scoping are buildable today via `PreToolUse` hooks without SDK migration; snapshot-and-hard-revert exists only in the embedded Agent SDK; bounded fix-retry budgets and hard budget enforcement have no native equivalent in either architecture. The finding splits along SDK-embedded vs. plain-CLI architecture rather than being a flat capability gap.

- **Exclusive-write scoping guarantee scope** — The claim that a hook denying a file path gives the LLM "no path to touch that file" was narrowed to reflect only what was verified: a string-match pattern blocking a specific redirection command. The guarantee depends on the hook's own matching logic, not an OS-level boundary, and doesn't cover indirect writes via variable substitution or symlinks, or writes from tools other than Bash, Edit, or Write.

## Open Threads

- **Indirect write paths and cross-tool write coverage** — The exclusive-write scoping capability wasn't tested against indirect writes using variable substitution or symlinks, or against write operations from tools other than Bash, Edit, or Write. Whether these represent actual gaps or acceptable limitations for the current use case is unresolved.

- **Bounded fix-retry budgets and hard budget enforcement** — Both require hand-rolled tracking in hook scripts today. Whether this limitation is acceptable for the pre-landing gate design or if native support should be prioritized is not addressed.
