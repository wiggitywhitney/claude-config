# Daily Summary — 2026-10-10

## Narrative

The developer spent the day wrapping up research work on Claude Code's hook events and configuration system, closing one major milestone while reopening a critical finding that had been incorrectly documented.

In the first session, they completed a detailed sweep of all 33 hook events in Claude Code version 2.1.296. They extracted the full event list from the binary using `strings`, verified it matched the official documentation, and created a detailed table labeling each event. The project currently uses three of them (`PreToolUse`, `PostToolUse`, `SessionStart`), and none of the 30 unused events replace existing hand-rolled mechanisms—those live in native git hooks instead. Three unused events stood out as candidates for future work: `UserPromptSubmit` for per-prompt rule enforcement, `PermissionDenied` for unattended auto-mode runs (though its interaction with the block budget still needs verification), and `Stop` for loop design. While doing this work, they also corrected an important inference in the decision log. An earlier finding had concluded that `UserPromptSubmit` was absent from version 2.1.221, but that was based on a misreading—the 2.1.221 enumeration only listed events that accept a matcher field, and `UserPromptSubmit` takes no matcher. Since 2.1.221 is no longer installed, they can't verify directly when the event was introduced, so they updated the docs to note only that it's confirmed present at 2.1.278 without claiming when it arrived. They also extracted and documented four new writing voice rules from recent sessions: state assumptions in hour estimates when someone else handles part of the work; use "video editor" instead of bare "editor" for clarity; avoid "As I mentioned" when referring back to earlier messages; keep episode posts focused on one story thread; and use short agreement as a good thread opener in Slack.

In the second session, the developer discovered and corrected a critical error in the project's findings about project-level `@`-imports. A probe from September 21st had concluded these imports never load into context, but that was wrong—the test used an incorrect import path that resolved to a nonexistent file. A fresh probe on October 10th at version 2.1.296 with file tools disabled showed that correctly written relative imports do load when a session starts, completely reversing the earlier conclusion. They updated the research files throughout the project to mark the old findings as superseded and documented what the re-probe actually revealed. They also noted that an earlier observation from August 3rd about home-relative imports still doesn't make sense given the path mistake, and both files involved had `paths:` frontmatter that hasn't been tested as a possible factor. The developer reopened the question of whether correctly pathed project imports survive context compaction—that's still unmeasured—and updated the byte budget guidance for upcoming work to count project-level imports at session start instead of excluding them.

## Key Decisions

- **detailed hook-event enumeration at 2.1.296** — All 33 hook events were extracted and labeled. Three are in use; 30 unused events were evaluated with none replacing hand-rolled mechanisms. Three unused events flagged for future consideration: `UserPromptSubmit`, `PermissionDenied` (pending verification of its interaction with the block budget), and `Stop`. This resolves an earlier finding that the binary was wider than the documentation.

- **Correction to version-introduction claim for `UserPromptSubmit`** — The 2.1.221 enumeration was only the subset of events accepting a matcher field, not the full set. Since `UserPromptSubmit` takes no matcher, its absence from that list proves nothing about when it was introduced. The claim that it arrived between 2.1.221 and 2.1.278 now lacks supporting evidence, and direct verification is impossible since 2.1.221 is no longer installed.

- **Writing voice rules extracted from recent sessions** — When an hour estimate assumes someone else handles part of the work, state that assumption in the same sentence. Use "video editor" rather than bare "editor" when the role may be ambiguous. Avoid "As I mentioned" when pointing back to earlier messages. Keep episode posts focused on one story thread. In Slack threads, a short agreement with the previous message is a good opener.

- **Project-level `@`-imports do load into context** — Reverses the September 21st finding. A re-probe with file tools disabled showed that correctly written relative imports (`@probe-import.md` instead of `@.claude/probe-import.md`) load when a session starts. The August 3rd observation using home-relative paths remains unexplained and may involve untested `paths:` frontmatter.
