# Monthly Summary — 2026-09

## Month in Review

The developer spent the week closing out audit findings and reconciling a long-lived feature branch with main. What started as straightforward bug fixes—the symlink checker marking dangling links as live, the card-making skill diffing the wrong branch—quickly surfaced a deeper architectural problem: nearly all installed skills and rules are symlinks into the working tree, which means branch state silently determines what loads in every session. This created cascading issues where skills measured different token counts on different branches, bugs silently reappeared when switching branches, and even verification rules and their fixes existed only on the current branch.

The developer also caught a series of tool integration problems: CodeRabbit CLI invocations had wrong flag names and missing push steps, git command mistakes led to false alarms about data loss (the developer learned `git diff --name-only` lists files that differ, not files unique to one side), and HTML comment handling in GitHub's review system made certain states invisible in the web interface. On the final day, they discovered that GitHub re-anchors inline comments whenever surrounding code stays unchanged, which created a false positive in review-coverage verification—a fix that ironically only exists on the current branch, reinforcing the branch-state dependency problem.

Throughout the week, the developer documented decisions deliberately: keeping the completion skill using pointers to shared workflow rules rather than inlining them (to avoid undoing compression work and reintroducing a truncation bug), the correct approach for merging conflicting journal files (union primary entries, take the fuller version of derived summaries), and shell command traps (zsh path-building silently truncates variables). Each problem went deeper than it first appeared, and the developer traced them back to root causes rather than patching symptoms.

## Accomplishments

- Fixed symlink checker incorrectly marking dangling links as live and corrected the card-making skill to diff the correct branch, preventing silent production of cards describing unrelated work.
- Discovered and documented that the codebase relies on symlinks for skills and rules, creating a design problem where branch state silently determines what loads—surfacing why skills measure different token counts across branches and bugs reappear when switching branches.
- Caught and fixed a false positive in review-coverage verification caused by GitHub's re-anchoring of inline comments, narrowing the check to only the reviews channel.

## Growth

- Learned the difference between git command behaviors (`git diff --name-only` lists files that differ, not files unique to one side) and caught a false alarm about data loss by understanding what the command actually does.
- Discovered and documented shell command traps, including how zsh path-building silently truncates variables and how GitHub re-anchors inline comments in ways that aren't visible in the web interface.
- Developed deeper understanding of the codebase's architecture around symlinks and branch dependencies, recognizing how a single design choice cascades across skills, rules, and verification logic.

## Looking Ahead

- The branch-state dependency problem remains unresolved—skills and rules load differently depending on what branch is checked out, and even fixes for verification rules exist only on the current branch and vanish when main is checked out. This is a design problem that will need architectural changes.
- CodeRabbit integration issues were patched but the underlying tool behavior around review states (paused vs. rate-limited) and how they're encoded in HTML comments may need further clarification or wrapper logic.
