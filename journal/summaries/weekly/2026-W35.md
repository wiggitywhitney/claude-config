# Weekly Summary — 2026-W35

## Week in Review

The developer spent the week reframing the project around sub-agent orchestration and building out the systems to support it, while simultaneously fixing a backlog of broken documentation and false claims that had accumulated in the repository.

The week started with a strategic pivot. Four of the five original complaints about the Claude configuration had already been resolved, leaving a new opportunity: automating verification through sub-agents rather than relying on manual review steps. This reframing elevated Viktor's and Michael's repositories to primary design sources and reversed the research phase order—studying practitioner workflows before platform capabilities, to avoid anchoring bias that would invisibly narrow the target through what documentation claims is possible.

On the first day, the developer completed an audit milestone, uncovering a structural problem where seven library scripts exist in two different directories with both copies live and diverged. They also built and partially tested a code reviewer sub-agent grounded in three real mistakes from the past week, writing 30 test assertions across three suites. The reviewer was made read-only by design, omitting Write and Edit tools entirely so findings-only is enforced by the platform. A push gate was implemented as a PreToolUse hook that blocks commits until a review verdict exists. However, the trial wasn't fully scored yet—three worktrees were left checked out at commits that introduced documented misses, ready for measurement.

The second day surfaced how mistakes propagate when consistency is enforced without verification. A shell command for loading secrets had been wrong in every copy since February; it got fixed in one place, then that fix was deliberately overwritten to match the two wrong copies for consistency. The developer scored the reviewer sub-agent against three real defects and found it caught 2 of 3—both cases where contradicting evidence existed elsewhere in the repository, but it missed a logic error that required reasoning about what code does. The trial also exposed that the reviewer's maxTurns cap truncated reviews silently, and each run cost 80,000 to 105,000 tokens. The developer corrected multiple false promises in the documentation: the PRD completion skill didn't auto-invoke despite claiming to, and a safety hook that had been deleted was still documented as blocking destructive operations. They also documented a known limitation where the autonomous mode skill's primary mechanism never takes effect because personal skills shadow project skills.

By the third day, the developer realized a bigger problem: the branch had accumulated 104 commits ahead of main with 44 never pushed to the remote, including twenty-two journal files marked as unrecoverable. The progress-recording skill had explicitly instructed against pushing, framing commits as safe local checkpoints. The developer rewrote it to make pushing normal, timing the push after CodeRabbit runs so findings can be triaged while work is still local. Then they deleted the push gate mechanism built the day before. CodeRabbit was already wired in and handled 15,000+ line diffs; the new gate truncated at around 1,000 lines and only checked that a note existed rather than that an actual review happened. With push now part of the progress workflow, the gate converted every update into a stop. The reviewer and `/diff-review` command were kept but rewritten as something you invoke deliberately rather than something that blocks a push.

The final day fixed the CodeRabbit review in the pre-push hook, which was running silently on every push and timing out as branches aged. The output filter was discarding findings when the tool's format changed. Rather than fix the filter, the developer removed the review from the hook entirely—it was already running once per milestone in the progress-update workflow where it actually finished and mattered. The security check that gates pushes stayed in place, and the PR merge gate still requires review. Tests were rewritten to verify the hook no longer runs any review.

## Highlights

- Built and partially scored a code reviewer sub-agent grounded in three real defects from the project's recent history, revealing it's strong at checking assertions against written evidence but unproven at reasoning about code logic.
- Fixed a critical command for loading secrets that had been wrong in every copy since February, then documented why consistency with an unverified copy is dangerous.
- Rewrote the progress-recording workflow to make pushing a normal step after CodeRabbit review, surfacing and fixing nineteen days of unpushed commits that had accumulated without notice.
- Removed unnecessary push-gate complexity that was truncating diffs and converting every progress update into a stop, consolidating CodeRabbit review to the milestone workflow where it actually finishes.

## Patterns

- Mistakes survive when consistency is enforced without verification—a broken command got copied, then the one correct copy was deliberately edited to match the broken ones for consistency, destroying the last working version.
- Documentation makes false promises about what the system does (auto-invoke, safety hooks that don't exist, partial features presented as complete), creating dangerous gaps between what users believe is protected and what actually is.
- Duplicate work accumulates silently—the code review ran both on every push and once per milestone; secrets got loaded from three different files; library scripts exist in two directories with both copies live and diverged.
