# Weekly Summary — 2026-W37

## Week in Review

The developer spent the week closing out review findings and tightening up a long-lived feature branch. The work fell into three main threads: fixing audit issues, reconciling the branch with main, and documenting gotchas that emerged during the process.

Early in the week, they addressed problems that surfaced during PRD review. The symlink checker was incorrectly marking dangling links as live, so they added a distinct BROKEN verdict and reordered checks to catch them first. The card-making skill was diffing the wrong branch, which would've silently produced incorrect cards—they made the instructions explicit and added a warning. Missing decisions got logged into the milestone body, and a false alarm about data loss on an unmerged branch was resolved by verifying the journal entries had already been copied to main in fuller versions. They also discovered that upstream skills had barely changed (20 lines in seven months) while local copies had diverged significantly (419 lines), which flipped their comparison strategy. They extracted an Anki capture step into a separate skill and consolidated duplicated rules, bringing both skill variants under token caps and fixing two live bugs in the process.

The major work came mid-week when they merged main into the branch to surface divergence issues early. This revealed a deeper problem: nearly all personally-installed skills are symlinks into the working tree, which means branch state silently determines what loads in every session. They demonstrated this with a concrete example where a skill measured different token counts on different branches. The merge also brought in a writing-voice rule that would merge silently into duplicates rather than flagging a conflict—a lesson about how long-lived branches combined with post-commit hooks create silent divergence git won't catch. They made sweeping updates across the codebase: fixed an incorrect `vals eval` command (should be `vals env`), created new agent definitions for diff-reviewing and design decisions, rewrote the make-autonomous skill to acknowledge that the SessionStart hook mechanism it relied on never actually worked, and corrected CodeRabbit integrations throughout (wrong flag names, missing push steps). They documented a merge policy for journal files (union primary entries, take the fuller version for summaries) and captured shell command traps that produce misleading results.

Late in the week, they pulled findings from code review into the PRD and corrected the review-coverage verification rule. GitHub re-anchors inline comments to the newest commit when the surrounding code stays the same, which created false positives—they narrowed acceptance criteria to check only the reviews channel. They also expanded the branch-dependence problem: not just skills but the rules directory itself is a symlink into the working tree, so every always-loaded rule follows whatever branch is checked out. Finally, they documented two distinct stop states in CodeRabbit's review service that had been conflated: rate limits (service refused the work) versus auto-pause (CodeRabbit throttled due to commit influx, self-inflicted by pushing during review). Both require manual intervention but have different remedies.

## Highlights

- Fixed symlink checker verdict logic and card-making skill branch diffing to prevent silent production of incorrect output
- Discovered upstream skills had barely changed while local copies diverged significantly, flipping the reconciliation strategy and reducing token usage by consolidating duplicated rules
- Identified that installed skills and rules follow branch state through working-tree symlinks, creating a design question about decoupling them for stability across branch changes
- Corrected review-coverage verification to avoid false positives from GitHub's re-anchoring of inline comments
- Documented CodeRabbit's two distinct stop states (rate limit vs. auto-pause) and the proper detection method using raw comment body text

## Patterns

- Recurring discovery of silent divergence and false positives: the symlink checker marking wrong verdicts, the card-making skill diffing the wrong branch, git merge silently creating duplicates, GitHub re-anchoring comments, and CodeRabbit's stop states hiding in HTML comments. Each required explicit, mechanical verification steps rather than relying on intent.
- Branch-state coupling emerging as a systemic issue: skills as symlinks, rules as symlinks, and generated files from post-commit hooks all mean the codebase behaves differently depending on which branch is checked out. This surfaced as a design question with implications for future migration decisions.
- Self-inflicted problems from workflow habits: pushing multiple times during a CodeRabbit review window triggers auto-pause, and long-lived branches combined with post-commit hooks create merge conflicts git won't flag. Documentation was updated to make these patterns explicit.
