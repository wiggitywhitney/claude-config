# Weekly Summary — 2026-W37

## Week in Review

The developer spent the week closing out audit findings and reconciling a long-lived feature branch with main, surfacing a series of interconnected problems around documentation accuracy, branch state dependencies, and tool behavior.

The work started with tightening up review findings from PRD #109. The symlink checker was incorrectly marking dangling links as live, the card-making skill was diffing the wrong branch, and several decisions that had been logged never made it into the milestone body. A false alarm about data loss turned out to be a git command mistake—`git diff --name-only` lists files that differ, not files unique to one side. The developer verified the supposedly lost journal entries had already been copied to main in fuller versions. Beyond fixing these issues, they documented a deliberate choice to keep the completion skill using pointers to shared workflow rules rather than inlining procedures, since inlining would undo compression work and reintroduce a truncation bug that had lost important steps.

The second day involved merging main into the feature branch to surface divergence early. This exposed a bigger picture: the codebase relies heavily on symlinks into the working tree for both skills and rules, which means branch state silently determines what loads in every session. The developer documented concrete examples where this caused problems—a skill measuring different token counts on different branches, and a compaction-cap defect that silently reappeared when switching back to main. They also caught and fixed several tool integration issues: CodeRabbit CLI invocations had wrong flag names and missing push steps, and the pre-merge verification script couldn't distinguish between "no review found" and "API call failed."

The merge also surfaced a merge policy problem. When four journal files came in with add/add conflicts, the developer documented the right approach: primary entries get unioned because either side may contain unique records, while derived summaries take the fuller version. They also documented shell command traps—not just the git diff mistake from earlier, but a zsh path-building feature that silently truncates variables.

On the final day, the developer caught a false positive in the review-coverage verification rule. GitHub re-anchors inline comments to the newest commit whenever their surrounding code stays unchanged, so an inline comment's commit ID could point to a newer commit than the review that actually created it. The fix narrowed the check to only the reviews channel, which records what was genuinely reviewed and doesn't move. This discovery extended the branch-dependence problem even further: the review-coverage correction exists only on the current branch and vanishes when main is checked out. Late in the day, the developer also clarified two distinct stop states in CodeRabbit's review service that had been conflated in the workflow rules. Both "review paused" and rate-limit notices hide inside HTML comments in the PR comment body, making them invisible in the GitHub web interface unless you grep the raw text without stripping tags.

## Highlights

- Fixed symlink checker incorrectly marking dangling links as live, and clarified card-making skill to diff the correct branch, preventing silent production of cards describing unrelated work.
- Discovered and documented that nearly all installed skills and rules are symlinks into the working tree, meaning branch state silently determines what loads across every repository—surfacing a design problem that causes skills to measure different token counts on different branches and bugs to silently reappear when switching branches.
- Caught and fixed a false positive in review-coverage verification where GitHub's re-anchoring of inline comments made in-flight reviews appear complete.

## Patterns

- Branch state dependencies kept surfacing throughout the week—first as a hidden issue with skills and rules, then expanding to include verification rules and their fixes, creating a widening circle of code that silently changes behavior based on what branch is checked out.
- Tool integration issues appeared repeatedly: CodeRabbit CLI flag names, missing push steps, git command misreadings, and HTML comment handling all required fixes or clarification.
- The developer kept discovering that problems went deeper than initially apparent—a false alarm about data loss turned into a git command lesson, a merge conflict became a documented policy, and a single false positive expanded into a wider branch-state problem.
