# Weekly Summary — 2026-W38

## Week in Review

The developer spent the week documenting and evaluating a configuration audit project, with most of the work focused on settling critical open questions and capturing practical gotchas from tool usage.

On Day 1, they conducted hands-on testing of the sandbox and code reviewer capabilities rather than relying on documentation alone. This empirical approach revealed that earlier research needed correction: the sandbox now routes network approvals through a classifier instead of prompting per domain, and a concrete TLS error in `gh` (the only tool actually tested) traced to a certificate verification failure fixable with a one-line exemption. They also discovered that `gcloud` and `terraform` weren't tested despite being documented as sharing the same mechanism. On the code reviewer front, they found evidence that Viktor had a disabled all-Claude alternative in his configuration, which proved stronger than running a new test for deciding against Claude-on-Claude review. The developer also identified three code-review implementations running simultaneously and deferred consolidating them to the next milestone since the work requires replacing rather than absorbing behavior. They committed four new gotcha files documenting practical problems like WebAssembly dependencies, missing documentation, and sandbox defaults, along with repairs to two documented commands that couldn't work as written.

Day 2 focused on settling two critical open questions from Milestone B1. First, they resolved a six-week-old question about whether project-level imports get compacted away. They built a measurement apparatus by adding a temporary import and hooking into instruction-load events, which showed the import produced no record after compaction. However, the import was added mid-session, leaving ambiguity about whether it failed to survive compaction or never loaded in the first place—both would look identical. They documented the measured result precisely while acknowledging this limitation, and the practical consequence stayed the same: project-level imports must be treated as first-load-only. Second, they ran three targeted probes to prove the sandbox escape hatch is model-mediated, not automatic. With it disabled, commands stayed blocked. With it enabled but the model instructed not to retry, they stayed blocked. With it enabled and the model free to act, the model re-issued the command with the escape parameter and succeeded. This closed the open question and clarified the documentation.

Day 3 was spent correcting and narrowing claims flagged by code review. The developer revised the sandbox work to accurately reflect that only `gh` was tested, softened claims about Viktor's configuration from proof of rejection to evidence of preference, and removed imprecise language throughout. They also clarified the byte-budget language in the PRD to distinguish between initial-load and post-compaction budgets, added a step to the Docker/Colima probe to start the service if it's stopped, and fixed stale byte-budget instructions in Milestone C1 that assumed project-level imports would be re-injected.
