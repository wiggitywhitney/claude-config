# devbox (Jetify) Gotchas

- **No Homebrew install path exists** — not a renamed tap, no tap at all. `brew install devbox` and `jetpack-io/devbox/devbox`/`jetify-com/devbox/devbox` do not work. The only local-machine install method is: `curl -fsSL https://get.jetify.com/devbox | bash`. An open GitHub feature request asking for brew support (#76, opened 2022) is still unresolved. For CI specifically, an official `jetify-com/devbox-install-action` GitHub Action exists (documented on a separate CI-specific page, not the general install page) — don't assume the curl script is the only option in a workflow file.
- **The official curl installer hardcodes `/usr/local/bin` and requires sudo — no flag or env var overrides the install directory.** Verified by fetching the script directly: `INSTALL_DIR="/usr/local/bin"` is a `readonly` constant, and the only supported flag is `-f`/`--force` (also settable as `FORCE=1`) to skip the interactive confirm prompt — it does not skip the sudo requirement. On a machine where the account isn't a sudoer (e.g. a managed device with no admin rights until temporarily escalated), the installer fails with "is not in the sudoers file" even with `-f`. Workaround: download the release tarball directly (`gh release download <version> --repo jetify-com/devbox --pattern 'devbox_<version>_darwin_arm64.tar.gz'`), extract it, and place the `devbox` binary in a directory already on `PATH` that doesn't require root — `/opt/homebrew/bin` is user-writable on an Apple-silicon Homebrew install and works as a drop-in substitute. Confirmed 2026-09-18.
- **Never install Nix separately.** Devbox auto-installs Nix on first `devbox shell`/`devbox run` if it isn't already present (multi-user mode on macOS, single-user on Linux/WSL2). **The macOS Nix install itself also requires root** (to create the `/nix` APFS volume) — `nix-installer` shells out to `sudo` automatically, so any `devbox` subcommand that triggers the first-run install (even a read-only one like `devbox run --list`) will hit the same sudoer error on a non-admin account. If a self-service escalation tool is available (e.g. `Privileges.app` on a managed Mac), granting temporary admin and re-running the same `devbox` command lets the installer complete via `sudo` without any special flag — no separate manual Nix install step is needed once elevated. Confirmed 2026-09-18.
- Custom scripts live under `shell.scripts` in `devbox.json`, each value a string or array of command strings:
  ```json
  { "shell": { "scripts": { "my-script": "some-command --flag" } } }
  ```
  Invoke with `devbox run my-script`. Scripts run in an interactive devbox shell that terminates when the script finishes.
- **Don't `source` a helper script from `init_hook` and then run it via `devbox run`** — this throws a "file not found" error in an open bug (#2108, #2607). Use `bash script.sh` instead of `source script.sh`.
- The `devbox.json` `$schema` field/URL is versioned and evolving — don't assume an old tutorial's schema URL is current; check `https://raw.githubusercontent.com/jetify-com/devbox/<version>/.schema/devbox.schema.json` at implementation time.
